CINEGRAPH COMPANION — AGENT HANDOFF / PROJECT CONTEXT
Last updated: 2026-10-13

PURPOSE
=======
Continue development of CineGraph Companion, a Chrome extension for a general audience. It should help users discover movies that match their cinematic taste while they browse supported streaming/catalogue sites. The extension detects or receives movie metadata, sends normalized title data to a CineGraph scoring service, and displays match bands and explanations in the extension UI (and, where explicitly permitted, as inline page badges).

The extension-side work assigned to this developer includes:
- Chrome extension side panel
- One site adapter, initially tested against a local demo catalogue
- Match badges / displaying scoring results
- Backend integration once the team's scoring endpoint is ready
- Extension QA and debugging

IMPORTANT PRODUCT DIRECTION
===========================
The user wants this to work for general users, across multiple streaming sites, rather than being hardcoded to a single local URL. They want a reusable architecture, not a hardcoded collection of movie-title-to-score mappings.

Use this as the desired direction, but do NOT promise automatic compatibility with every streaming site. Each site has its own DOM and terms/access rules. Build a shared adapter interface and enable integrations only where the site permits the proposed access. Use explicit user-initiated analysis and narrowly scoped permissions by default. Never collect login credentials, cookies, full page HTML, or viewing/playback history by default. Do not build a silent or large-scale catalogue scraper.

LEGAL / PERMISSION CONSTRAINT
=============================
During the previous development conversation, official IMDb terms/help and Hotstar terms were identified as restricting automated extraction/scraping without permission. Before implementing any streaming-site-specific extraction or DOM injection, verify the applicable current terms and permitted access method. Do not add a broad all-sites content script simply to bypass per-site restrictions. Prefer official/authorized APIs, licensed metadata, or user-entered title lookup when page extraction is not permitted.

DESIRED ARCHITECTURE
====================
Build toward a structure similar to:
- manifest.json: MV3 permissions and side panel
- background.js: service worker, side-panel behaviour, user-initiated request coordination
- sidepanel.html / sidepanel.css / sidepanel.js: UI and an explicit “Analyze this page” action (or manual-title fallback)
- content.js: thin page integration layer; collects only supported metadata and renders results where allowed
- adapters/: one adapter per permitted site, each returning the same normalized shape
- scoring-client.js: shared API client / response validation; replace mock scoring without rewriting DOM logic
- optional development-only mock service/fixtures, clearly labelled as fake data

Normalized metadata target:
{ raw_title: string, year?: number | null, source?: string }

For each adapter:
- Match only that site's page/URL patterns.
- Avoid extracting unrelated page text or sending entire HTML.
- Handle dynamic content with bounded work and avoid duplicate badges if a page updates.
- Handle no result / unresolved titles cleanly.
- Include clear user action and permission context before analysis.
- Do not access playback progress, watch history, account data, cookies, or credentials.
